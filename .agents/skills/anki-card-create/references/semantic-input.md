# Контрактный пример: семантический вход и пустое поле результата

Это синтетический пример локального состояния агента, **не** схема CLI
`create` и не дополнение к `.anki-repo/create.yaml`. Поля фактической модели
всегда проверяются через `models`. Сопоставление семантического входа с
потребителем сохраняется вне Git; оно не меняет контракт обработчиков Rust.

Дано: модель с синтетическим UUID `11111111-2222-4333-8444-555555555555`,
полями `Лексема`, `Кандзи`, `Ударение`; её правила назначают `kanji_assets`
полю `Кандзи`, `pitch_accent` полю `Ударение`. Пользователь передал слово
`海辺` и чтение `うみべ`. Новая заметка перед получением ресурсов:

```json
{
  "guid": "synthetic-note",
  "note_model_uuid": "11111111-2222-4333-8444-555555555555",
  "fields_by_name": {
    "Лексема": "海辺",
    "Кандзи": "",
    "Ударение": ""
  },
  "semantic_input": {
    "surface": "海辺",
    "reading": "うみべ",
    "source": "явный запрос пользователя"
  },
  "media_consumers": {
    "kanji_assets": "Кандзи",
    "pitch_accent": "Ударение"
  }
}
```

Ожидаемая подготовка без заполнения выходных полей:

- зависимости кандзи — `海`, `辺`, полученные из `semantic_input.surface`;
- pitch-план ниже, полученный из `semantic_input`, без чтения `Ударение`;
- пустые `Кандзи`/`Ударение` не означают отсутствие зависимостей;
- после подтверждения владельцем ссылки заполняют указанные поля-потребители;
  при доказанном `no_pitch_accent_on_source` `Ударение` остаётся пустым;
- если явный вход удалён и источник не сопоставлен, агент уточняет слово,
  без угадывания его по именам полей.

```json
{
  "schema_version": 1,
  "items": [{ "surface": "海辺", "reading": "うみべ" }]
}
```

Тот же результат должен получаться при других именах текстового и выходного
полей после явной проверки модели и сопоставления. Ни `Лексема`, ни
`Ударение`, ни UUID примера не являются обязательными именами или значениями
репозитория. Повторные заметки с тем же запросом делят зависимость; разные
известные чтения одной `surface` требуют разрешения конфликта владельцем.
