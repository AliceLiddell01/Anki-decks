# Поверхности живой проверки Anki-decks

Этот документ описывает **существующие** границы проекта. Перед запуском
конкретной команды перечитай указанного владельца: CLI, опции, ограничения,
поддержка ОС и режимы могут измениться.

## Корневая рабочая область Cargo и CI

- Сборка и тесты запускаются из корня Anki-decks с корневым `Cargo.toml`
  и `Cargo.lock`. Не создавай отдельную сборочную среду для смок-проверки.
- Штатный минимум: `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo test --workspace --locked`.
- Серверный CI в `.github/workflows/ci.yml` добавляет проверку Cargo с нужным
  профилем, проверки экспортов и доменных корпусов, проверку Agent Skills и MSRV.
  Не выдавай локальный сокращённый прогон за полный CI.
- Проверка метаданных нового навыка —
  `python3 .github/scripts/check_skill_contracts.py --root .`.
  Это штатный проверяющий скрипт репозитория, **не** разовый помощник.

## CrowdAnki: `anki-repo`

Владельцы: `tools/anki-repo/README.md`,
`.codex/context/03-VERIFICATION.md`.

- Настоящий CLI читает фактические `deck.json`, модели, поля,
  `crowdanki_uuid`, `guid`, ссылки `media_files`; имена текущих колод
  и полей — входные данные, а не фиксированные значения в помощниках.
- Пример реальной проверки без записи в экспорт из корня:
  `cargo run --quiet --bin anki-repo -- validate <путь-к-экспорту>`.
  Используй и `models`, `inspect`, `qa`, `find` по назначению.
- `edit`, `create`, `retire`, `migrate-media` пишут только по своему
  явному контракту: проверь dry-run, затем `--apply` на **копии** экспорта,
  повторяемость, отсутствие изменений посторонних полей и реальный
  `validate` после записи.
- `visual-report` проверяет реальные шаблоны и содержимое «до/после»;
  выходной каталог отчёта — локальный артефакт, не часть `decks/**`.
  Нельзя объявлять визуальное подтверждение только по синтетическому HTML
  собственного помощника.

## Kanji/Pitch: `asset-store`

Владелец: `tools/asset-store/README.md`.

- `kanji-assets` и `pitch-assets` имеют штатные команды получения,
  проверки и пакетной обработки. **Возобновление различается:**
  `pitch-assets` поддерживает явную `batch resume`, а `kanji-assets`
  продолжает сохранённый пакет повторным `batch run --batch-id <id>`.
  Используй настоящие команды и планы; проверяй фактические результаты
  и контрольные точки вместо их воспроизведения самодельной реализацией.
- Для кандзи live-провайдер — настоящий Yarxi; для тонового акцента —
  фактическая интеграция с JPDB. Не подменяй браузер фиктивными ответами.
  При неожиданной сетевой недоступности результат `NOT_RUN`/`PARTIAL`, не
  «успешная имитация».
- `browser_runtime.rs` владеет Chromium/CDP, `TempWorkspace` —
  пространством среды выполнения, запуском профиля, проверкой
  принадлежности и очисткой.
  Наличие `CHROME_BIN`/`CHROMIUM_BIN` и сертификатные исключения
  определяет владелец; не вводи для теста глобального выключения TLS.
- Реальная визуальная приёмка сверяет фактически созданные PNG/GIF,
  идентичность статьи/символа, диагностические данные и применимый
  человеческий осмотр. Одна только успешная загрузка браузера или HTTP-ответ
  не доказывает корректность медиа.
- Уже существующие `yarxi_dark_acceptance`,
  `jpdb_pitch_acceptance` и сценарии ротации с отдельной возможностью
  Cargo проверяй по их задокументированному назначению. Их постоянное размещение оценивается
  по повторному использованию, а не автоматически по слову «acceptance».
  Возможности тестовой сборки не считаются эквивалентом обычной сборки.

## Данные, источники, окружение

- Канонические `decks/**` и `.asset-store/**` защищены контрактами
  владельцев. Создавай отдельные копии/входы для обратимых проб.
- Проект использует Linux-ориентированные процессы и временные ресурсы,
  включая `/proc`, UID и Chromium, а агент может запускать вспомогательный
  инструмент в Windows/PowerShell или WSL. Не предполагай, что разные ОС
  поддерживают одинаковую инструментальную диагностику.
- Каталог `.codex/local/scripts/<task>/` предназначен для **кода помощника**,
  `.codex/local/reports/<task>/` — для планов, сводок и указателей на внешние
  доказательства. Штатные ZIP-архивы приёмки остаются вне рабочей копии
  по контракту `tools/asset-store/README.md`. Ресурсы Chromium и системные
  временные объекты оставь их настоящему владельцу.
- Проверь перед запуском состояние Git, допустимость сетевых обращений,
  доступность браузера и тестовых учётных данных; не записывай секреты в отчёты.
