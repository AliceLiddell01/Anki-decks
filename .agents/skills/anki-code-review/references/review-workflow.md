# Порядок независимого ревью

## 1. Область и требования

По Git и GitHub установи точный репозиторий, объект проверки, base/head,
merge-base при необходимости, состояние незакоммиченных изменений и файлы diff.
Для PR проверь исходную ветку и целевой коммит, а не полагайся только на
описание. Восстанови постановку задачи из доступных источников и проектных
контрактов; отдельно фиксируй недоступные требования.

## 2. Анализ

Изучи каждую значимую область изменений, затем контекст: callers, зависимости,
форматы данных, соседние тесты, повторное использование и отрицательные
сценарии. Сравни заявленное поведение с реализованным. Ищи регрессии,
необоснованные исключения под конкретный случай, старую реализацию,
нерациональную сложность и непропорционально слабые тесты.

Используй [критерии](review-criteria.md), включая безопасность, обработку
отказов, ресурсы, конкуренцию и язык. Не выдавай сигнал статического анализа
за подтверждённый дефект без проверки причинно-следственной цепочки.

## 3. Проверки

Запусти доступные существующие проверки проекта, релевантные изменению;
для Rust ориентируйся на инструкции корневого workspace и CI. Если окружение
не позволяет собрать проект или выполнить отдельный тест, явно запиши это
ограничение. Не объявляй непроверенное «зелёным».

## 4. Вывод

Следуй [политике замечаний](finding-policy.md). Для каждого дефекта:
серьёзность, файл и строка, конкретный сценарий, нарушенный контракт,
последствие и направление исправления. Объединяй повторные проявления одной
причины. Отделяй факты от предположений и ранее существовавших проблем.

В конце дай статус CLEAN/COMMENT/REQUEST_CHANGES/INCOMPLETE, соответствие исходным
требованиям, результаты проверок и реальные ограничения. Отсутствие findings
не означает гарантии отсутствия ошибок.

## 5. Независимость

Не запускай CodeRabbit без отдельного положительного поручения. Если
пользователь запросил сравнение, сначала заверши собственный анализ,
затем сопоставь его с предоставленным или доступным внешним результатом;
не выдавай внешние замечания за свои. Обычное ревью не изменяет PR.
Отдельное поручение исправить и опубликовать обрабатывай по Git-workflow.
