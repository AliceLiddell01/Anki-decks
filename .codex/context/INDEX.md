# Индекс контекста Codex

Папка содержит короткий долговременный контекст для работы с CrowdAnki-колодами. Это не журнал конкретного PR и не копия содержимого самих колод.

## Как пользоваться

1. Прочитать корневой `AGENTS.md`.
2. Определить конкретную колоду и тип изменения.
3. Открыть только относящиеся к задаче документы из таблицы ниже.
4. Проверить все предположения по фактическому JSON текущей ветки.
5. Для большого экспорта предпочитать поиск по ключам и программный разбор полному чтению файла.

маршрутизируй к ним, а не заводи здесь второго владельца их процедуры.

## Инструменты

`tools/anki-repo` — самостоятельный Rust CLI для одного CrowdAnki-экспорта. Он разрешает связи `note_model_uuid` → `flds[].ord` → `fields` и предоставляет `inspect`, `find`, `stats`, `validate`, `qa`, `review`, `review-check`, `models`, `visual-report`, `edit`, `create`, `retire` и `migrate-media` с человекочитаемым и JSON-выводом; предпочитай его ручному чтению многомегабайтного `deck.json`. Для проверки содержимого карточек используй `qa` (детерминированные findings по фиксированному реестру правил) и `review` (компактный batch заметок для внешнего агента), а предложения агента проверяй через `review-check`: он ничего не пишет и выдаёт готовый запрос для `edit`. Перед созданием заметки смотри фактическую схему полей командой `models`. `edit` меняет значение существующего поля, `create` добавляет заметку в существующую колоду и модель, `retire` дописывает тег вывода из обращения, а `migrate-media` переводит только доказанные ссылки на legacy-имя домена. Каждая изменяющая команда по умолчанию работает как dry-run и требует `--apply` для записи. `create` может материализовать только проверенные media-файлы, разрешённые явными правилами домена; `migrate-media` — разместить канонический файл и удалить legacy-файл после доказательства identity и проверки потребителей. Только `migrate-media` может менять media-ссылку существующей заметки. `visual-report` собирает статический офлайн-отчёт о различиях двух состояний экспорта и ничего не пишет в сам экспорт. Toolkit не вызывает LLM API: содержательное суждение делает внешний агент.

`tools/asset-store/README.md` — канонический контракт отдельной библиотеки Rust и бинарника `kanji-assets` для ресурсов, которыми управляет программа. Они не читают пользовательские media и не зависят от содержимого колод.

## Что здесь не хранить

- полный снимок конкретной колоды;
- номер текущего PR, ветку или SHA;
- временные результаты ревью;
- большие списки заметок или media-файлов;
- сведения, которые можно надёжно получить из самого JSON;
- процедуры repository skills — ими владеет сам
  `.agents/skills/<name>/`; не дублируй их здесь.
