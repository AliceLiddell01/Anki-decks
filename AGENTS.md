# Инструкции для агентов Anki-decks

## 1. Назначение

Этот репозиторий хранит персональные Anki-колоды в JSON-формате CrowdAnki и контекст для их безопасного анализа и редактирования.

Отвечай пользователю, пиши документацию и сообщения коммитов на русском языке. Точные имена JSON-ключей, путей, UUID, HTML/CSS, японских выражений и внешних инструментов сохраняй без перевода.

## 2. Источники истины

Для задачи над конкретной колодой используй источники в таком порядке:

1. целевой CrowdAnki JSON в текущей ветке;
2. связанные с ним `note_models`, `deck_configurations`, дерево `children` и сами `notes`;
3. относящиеся к задаче документы `.codex/context/`;
4. официальная документация CrowdAnki/Anki, только если требуется уточнить внешний формат или поведение.

Контекстные документы помогают навигации, но не заменяют проверку фактического JSON.

## 3. Маршрутизация контекста

Перед работой с колодой:

1. прочитай `.codex/context/INDEX.md`;
2. определи область изменения;
3. открой только документы, которые владеют этой областью;
4. не загружай большой JSON целиком, если задача решается точечным поиском или скриптом.

Базовая карта репозитория — `.codex/context/01-PROJECT-MAP.md`.
Схема и безопасная навигация по CrowdAnki JSON — `.codex/context/02-CROWDANKI-JSON.md`.
Проверки после изменения — `.codex/context/03-VERIFICATION.md`.

Для структурного анализа экспорта используй read-only toolkit `tools/anki-repo`
(`inspect`, `find`, `stats`, `validate`) вместо ручного чтения многомегабайтного
`deck.json`. Его контракт описан в `tools/anki-repo/README.md`.

## 4. Инварианты CrowdAnki

- Не меняй `crowdanki_uuid`, `guid`, `note_model_uuid` и `deck_config_uuid` без явной причины.
- Не меняй порядок полей заметки вслепую: сначала разреши `note_model_uuid` и сопоставь `fields` с `note_models[].flds[].ord`.
- Не считай `media_files` содержимым media: это список ссылок/имён файлов, а не бинарные данные.
- Не смешивай правку лингвистического содержимого с изменением модели карточки, HTML/CSS или настроек планировщика, если задача этого не требует.
- При массовой правке используй детерминированный скрипт или точечное преобразование; избегай ручного переписывания многомегабайтного JSON.
- Сохраняй существующее форматирование JSON, если нет отдельной задачи на нормализацию.
- Не удаляй неизвестные ключи только потому, что они не нужны текущей задаче.

## 5. Работа с японскими словарными колодами

Текущий целевой путь словарной колоды:

`decks/japanese/words/`

Для знакомого экспорта ожидается модель заметки со следующими полями:

1. `Слово`
2. `Часть речи`
3. `Значение`
4. `Ударение`
5. `Пример`
6. `Похожие слова`

Это удобная карта, а не лицензия на предположение: после добавления или замены JSON всегда сверяй фактический `note_model_uuid` и `note_models[].flds`.

## 6. Изменения и Git

- Одна самостоятельная задача — одна рабочая ветка и один PR.
- Не работай напрямую в `main`.
- Не сливай PR без отдельной явной команды пользователя.
- В PR описывай фактический набор изменений и выполненные проверки.
- Не добавляй в постоянный контекст номер текущего PR, SHA, временный план или разовые результаты ревью.

## 7. Skills

`.agents/skills/` зарезервирован под будущие специализированные skills.

Пока пользователь явно не попросил создать или изменить skill, не добавляй туда реализацию и не придумывай преждевременную автоматизацию.
